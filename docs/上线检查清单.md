| 网页端 `admin/pages/SettingsPage.tsx` 的占位文案 | 探索八字玄机 | 传统历法 | 只影响后台输入框的灰字提示，可选 |
| 后端 `minghub/admin_api/views.py` / 前端 `ConfigContext` 的 defaults | 探索八字玄机 · 洞悉人生运势 | 传统历法 · 四柱排盘工具 | 只影响「配置被清空后」的兜底值，可选，建议一并改 |
| 小程序 关于页 · 个人微信副标题 | 命理交流 · 深度咨询 | 传统文化交流 | ✅ 已改 |
| 小程序 关于页 · 公众号副标题 | 教程 · 案例 · 考据 | 保持不变 | — |

**为什么盯这一句**：微信审核对「算命 / 预测 / 改运 / 运势」这类表述敏感，`site_subtitle` 是
首页第一眼看到的字，风险最高；「玄机」这类词本身不算违禁，但和「运势」连在一起就容易被读成测算服务。
定位成「历法工具 + 古籍命例检索」，审核与用户预期都更稳。

顺带一提：命例库的**反馈正文**是数据库内容（古籍原文与用户分享），不在这份清单里。
建议抽查几条确认没有个人隐私信息（真实姓名 / 手机号 / 身份证号）。

## 五、隐私与数据（T-6.5）

代码侧确认：**没有使用任何需要用户单独授权的隐私接口**（已逐项 grep 核对）。实际用到的只有：

### 5.1 逐项核对（2026-09-24 按官方对照表核实）

官方对照表：[小程序隐私协议开发指南 · 开发者处理的信息](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/miniprogram-intro.html)
（原文：「处理的信息 / 接口或组件」一一对应，且「微信会根据小程序版本隐私接口调用情况**展示必填项**」）。

| 能力 | 我们的用途 | 官方对照表里的归属 | 要声明吗 |
| --- | --- | --- | --- |
| `wx.setClipboardData` | 关于页「复制」页脚文案 | **读取你的剪切板**（`setClipboardData` / `getClipboardData`） | ✅ **要勾** |
| `wx.login` | 换 code → 服务端换 openid（账号标识） | **不在这张表里** | ❌ 不勾（无对应项） |
| 昵称 | 用户在「我的设置」里**手输**（`wx.showModal`） | 「收集你的昵称、头像」对应的是 `<button open-type="chooseAvatar">` / `<input type="nickname">` / `getUserProfile`，**我们一个都没用** | ❌ 不勾 |
| `image` 加载站点头像 / 二维码 | 展示作者头像与二维码 | 不涉及 | ❌ 不勾 |
| 位置 / 相册 / 摄像头 / 麦克风 / 通讯录 / 手机号 / 蓝牙 / 微信运动 / 传感器 / 日历 | — | — | ❌ 全部不勾（代码里 grep 过，一个都没用） |

> ⚠️ **本节 v1～v3 曾把 `wx.setClipboardData` 判为「不是隐私接口」，那是错的**——官方把它和
> `getClipboardData` 一起归入「读取你的剪切板」。漏勾的后果：真机上点「复制」会被拦
> （基础库 ≥ 2.32.3 会先弹隐私授权；未声明则直接失败）。

### 5.2 用户会看到的隐私弹窗

勾了「剪贴板」之后，首次点「复制」会触发微信的隐私授权。基础库 ≥ 2.32.3 时，
若开发者未接 `wx.onNeedPrivacyAuthorization`，**微信会用官方默认弹窗**，不需要我们写代码。
**这意味着真机验收第 10 项之外，还要顺带点一次「复制」看弹窗是否正常。**

`wx.login`（登录）不触发隐私弹窗，用户点「登录」不会看到弹窗——这是正常的，别误以为漏配。

数据存放：用户数据在自有服务器（`110.40.159.5`）的数据库里，与网页端共用；小程序本地只存
token（`mhsy:` 前缀）与排盘偏好。
