## 二、⚠️ 必须先解决的两个坑

### 坑 1（会挂站）：新版 `settings.py` 强制要求 `SECRET_KEY`

`5832acc` 里为了修安全问题，把 `SECRET_KEY` 改成了**没有环境变量就拒绝启动**：

```python
SECRET_KEY = os.getenv('SECRET_KEY', '')
if not SECRET_KEY:
    if DEBUG:
        SECRET_KEY = 'django-insecure-local-dev-only'
    else:
        raise ImproperlyConfigured('缺少环境变量 SECRET_KEY。…')
```

而**顶层 `docker-compose.yml` 的 backend 段根本没有传 `SECRET_KEY`**（实测容器内 `env` 确认只有 6 个 `DB_*`）。
后端仓库里的 `.env`（`/root/minghaishiyi/minghaishiyi_backend/.env`）**被 `.dockerignore` 排除**（`.env` / `.env.*`），进不了镜像，容器里 `load_dotenv()` 读不到任何东西。

👉 **结论：如果直接 `git pull` + `docker compose up -d`，后端容器会启动失败 → 整站 502。**
必须先做第四节的 Step 3、Step 4。

### 坑 2（登录会 503）：`WX_APPID` / `WX_APPSECRET` 同样没传

`settings.py` 读的是环境变量，compose 没传 → 容器里为空 → `/api/auth/wechat/` 返回 **503**。
同样在 Step 3 / Step 4 解决。

### 顺带说明（不影响功能）

- 服务器上两个 git 仓库的 `.git/objects/pack/` 里有 macOS 的 `._*` 垃圾文件，git 每次都打印
  `error: index file .git/objects/pack/._pack-xxxx.idx is too small`。**这是噪音，不影响 `git pull`**
  （实测 `git fetch` / `git log` / `git status` 全部正常）。可选做 Step 7 清理。
- 两个仓库工作区都**干净**（无本地改动），所以 `git pull` 不会冲突。
- `minghaishiyi_backend/docker-compose.yml`、`minghaishiyi_frontend/docker-compose.yml` 都是
  **历史遗留的独立 compose，没有被使用**（`docker compose ls` 只列出顶层那一个）。别去动它们，也别在子目录里跑
  `docker compose up`，否则会起出重复容器抢端口。

### Step 2 · 生成 `SECRET_KEY`


### Step 3 · 创建 `/root/minghaishiyi/.env`

`docker compose` 会自动读取**项目目录**下的 `.env` 用于变量插值——注意是顶层目录，不是 `minghaishiyi_backend/.env`。

```bash
cat > /root/minghaishiyi/.env <<'EOF'
SECRET_KEY=把Step2的输出粘到这里
DEBUG=False
ALLOWED_HOSTS=www.minghaishiyi.cn,minghaishiyi.cn,110.40.159.5,127.0.0.1,localhost
CSRF_TRUSTED_ORIGINS=https://www.minghaishiyi.cn,https://minghaishiyi.cn,http://127.0.0.1:8000
WX_APPID=wx990ba3cc14bef05d
WX_APPSECRET=把微信后台的AppSecret粘到这里
EOF

chmod 600 /root/minghaishiyi/.env
```

**AppSecret 从哪拿**：`mp.weixin.qq.com` → 左侧「开发管理」→「开发设置」→「开发者ID」→ AppSecret 右侧「重置」。
（微信只显示一次，重置后旧的立即失效；如果小程序里没用过就没影响。）

### Step 4 · 修改 `/root/minghaishiyi/docker-compose.yml`

只需要改 `backend` 段的 `environment`，**在 `DB_PORT=3306` 后面追加 6 行**。
改完后该段应该长这样：

```yaml
  backend:
    build: ./minghaishiyi_backend
    image: minghaishiyi-backend:latest
    container_name: minghaishiyi-backend
    restart: always
    ports:
      - "7777:7777"
    volumes:
      - /data/minghaishiyi/uploads:/app/uploads
    environment:
      - DB_ENGINE=django.db.backends.mysql
      - DB_NAME=minghaishiyi
      - DB_USER=root
      - DB_PASSWORD=qq525277891..
      - DB_HOST=mysql
      - DB_PORT=3306
      # ↓↓↓ 本次新增 ↓↓↓
      - SECRET_KEY=${SECRET_KEY:?请先在 /root/minghaishiyi/.env 中设置 SECRET_KEY}
      - DEBUG=False
      - ALLOWED_HOSTS=${ALLOWED_HOSTS:-www.minghaishiyi.cn,minghaishiyi.cn,110.40.159.5,127.0.0.1,localhost}
      - CSRF_TRUSTED_ORIGINS=${CSRF_TRUSTED_ORIGINS:-https://www.minghaishiyi.cn,https://minghaishiyi.cn,http://127.0.0.1:8000}
      - WX_APPID=${WX_APPID:-}
      - WX_APPSECRET=${WX_APPSECRET:-}
    depends_on:
      mysql:
        condition: service_healthy
```

`mysql` 与 `frontend` 段**完全不动**。

> `${SECRET_KEY:?...}` 是刻意写的：万一 `.env` 没生效，compose 会直接报错并停止，
> 而不是静默用空值启动一个不安全的服务。

**改法一（推荐，自动追加）**：

```bash
cd /root/minghaishiyi
python3 - <<'PY'
p = 'docker-compose.yml'
s = open(p, encoding='utf-8').read()
add = """      - SECRET_KEY=${SECRET_KEY:?请先在 /root/minghaishiyi/.env 中设置 SECRET_KEY}
      - DEBUG=False
      - ALLOWED_HOSTS=${ALLOWED_HOSTS:-www.minghaishiyi.cn,minghaishiyi.cn,110.40.159.5,127.0.0.1,localhost}
      - CSRF_TRUSTED_ORIGINS=${CSRF_TRUSTED_ORIGINS:-https://www.minghaishiyi.cn,https://minghaishiyi.cn,http://127.0.0.1:8000}
      - WX_APPID=${WX_APPID:-}
      - WX_APPSECRET=${WX_APPSECRET:-}
"""
old = '      - DB_PORT=3306\n'
assert s.count(old) == 1, '定位失败，请手动改'
assert 'SECRET_KEY' not in s, '似乎已经改过了'
open(p, 'w', encoding='utf-8').write(s.replace(old, old + add))
print('OK')
PY
```

**改法二**：`nano /root/minghaishiyi/docker-compose.yml` 手动照上面加。

## 五、`depoly.sh` 要不要改

**要**，但改不改都不影响本次能否成功。建议改两点：

1. 前端代码已是最新时不必 `--no-cache` 重建——`--no-cache` 每次都要重装 npm 依赖，白烧 5 分钟。
2. 加一步部署后自检，失败就报警（可选）。

改后的建议版本：

```bash
#!/bin/bash
set -e
cd /root/minghaishiyi

echo "=== 拉取后端代码 ==="
cd minghaishiyi_backend && git pull origin main && cd ..

echo "=== 构建 + 重启后端 ==="
docker compose build backend
docker compose up -d backend

echo "=== 数据库迁移 ==="
docker compose exec -T backend python manage.py migrate --noinput

echo "=== 自检 ==="
sleep 5
code=$(curl -s -o /dev/null -w '%{http_code}' -X POST \
  http://127.0.0.1:7777/api/auth/wechat/ -H 'Content-Type: application/json' -d '{"code":"x"}')
echo "wechat 接口返回: $code"
[ "$code" = "400" ] || { echo "❌ 自检未通过，请 docker compose logs backend"; exit 1; }

docker image prune -f
echo "=== 部署完成 ==="
```

（前端发版时再单独 `docker compose build frontend && docker compose up -d frontend`。）
